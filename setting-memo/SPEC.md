## 1. 作るもの

4×4 のマスでタイルを滑らせ、同じ数字どうしをぶつけて合体させるパズル。2048 を作れば勝ち。
ブラウザだけで動く。サーバーは使わない。

### 今回やらないこと（time box を守るため）

- オンライン対戦、ログイン、サーバー保存
- タイルが実際に滑るアニメーション（→ 6 章の方針 A を採用）
- Undo（ひとつ戻る）機能
- 盤面サイズの変更（4×4 固定）

## 3. 盤面データの形式

4×4 の二次元配列。**空きマスは `0`**。

```js
board = [
  [2, 0, 0, 4],   // 一番上の行
  [0, 0, 2, 0],
  [0, 8, 0, 0],
  [0, 0, 0, 0],   // 一番下の行
];
```

- 位置は `[row, col]` の順（`row` が縦、`col` が横。どちらも 0〜3）
- `board[0][0]` が左上、`board[3][3]` が右下

## 4. 関数の約束（最重要）

### 4-1. `game.js` が提供するもの

#### `startGame()` → `state`

盤面を初期化し、タイルを 2 枚ランダムに置く。スコアを 0 に戻す。

#### `move(direction)` → `state`

`direction` は文字列 `"left"` / `"right"` / `"up"` / `"down"` のいずれか。
盤面を動かし、変化があれば新しいタイルを 1 枚追加する。

#### `getState()` → `state`

現在の状態を返すだけ（盤面は変更しない）。

### 4-2. `state` の中身

上の 3 つの関数は、すべて**同じ形のオブジェクト**を返す。

```js
{
  board:       [[2,0,0,4],[...],[...],[...]],  // 4×4。空きは 0
  score:       124,          // 合計スコア
  gainedScore: 8,            // 今回の移動で増えた分（演出に使う）
  moved:       true,         // 今回の入力で盤面が変化したか
  newTiles:    [[2, 3]],     // 今回 新しく出たタイルの位置 [row, col] の配列
  mergedTiles: [[0, 0]],     // 今回 合体して生まれたタイルの位置の配列
  isGameOver:  false,        // もう動かせないか
  isWin:       false         // 2048 が初めて出た瞬間だけ true
}
```

**`newTiles` と `mergedTiles` は UI 側の演出（ポンと拡大する CSS）に使います。** 空のときは `[]` を返すこと。

### 4-3. `ui.js` が提供するもの

#### `render(state)`

`state` を受け取って、盤面とスコアを画面に描き直す。

#### `showOverlay(type, score)`

`type` は `"gameover"` または `"win"`。結果画面を出す。

### 4-4. 処理の流れ（どちらが何を呼ぶか）

**入力を受け取るのは `ui.js` です。** `game.js` は呼ばれたら計算して返すだけ。

```
ページ読み込み
  → ui.js が startGame() を呼ぶ → 返ってきた state を render()

矢印キー / スワイプ
  → ui.js が move("left") などを呼ぶ
  → 返ってきた state を render()
  → state.isWin なら showOverlay("win", score)
  → state.isGameOver なら showOverlay("gameover", score)
```

## 5. ゲームのルール（ここに罠が集中しています）

実装前に、ロジック担当は必ずこの 5 項目を読んでください。

### ① 1 回の移動で、同じタイルは 2 度合体しない

```
[2, 2, 4] を左へ  →  [4, 4, 0, 0]      ← 正しい
                  →  [8, 0, 0, 0]      ← 間違い
```

### ② 合体は「進行方向に近い側」が優先

```
[2, 2, 2, 0] を左へ  →  [4, 2, 0, 0]   ← 正しい
                     →  [2, 4, 0, 0]   ← 間違い
```

### ③ 盤面が変化しなかった移動では、新しいタイルを出さない

壁に押し付けて何も動かないとき、タイルが増えてはいけない。
この場合 `moved: false` を返し、`newTiles` は `[]` にする。

### ④ 新しいタイルは 2 が 90%、4 が 10%

空きマスの中からランダムに 1 か所選んで置く。

### ⑤ ゲームオーバーの条件は 2 つ同時に満たしたとき

- 空きマスが 1 つも無い **かつ**
- 上下左右のどの方向に動かしても盤面が変化しない（＝隣り合う同じ数字が無い）

**「空きが無い」だけで終わらせると、まだ遊べるのに終了してしまいます。**

### ⑥ 勝利（2048 到達）でゲームは止めない

`isWin` は 2048 が**初めて**出た移動だけ `true`。以降は `false` に戻し、続けて遊べるようにする。

## 6. 描画方式：A（描き直し方式）で確定

**移動のたびに盤面を丸ごと描き直します。** タイルを実際に滑らせる方式（B）は採用しません。

- 実装が簡単で、5 時間に収まる
- `game.js` は「タイルがどこからどこへ動いたか」を管理しなくてよい
- 代わりに `newTiles` / `mergedTiles` を返し、**その 2 種類だけ CSS で一瞬拡大する**
  → アニメーション無しより体感がかなり良くなる。CSS だけで完結するので UI 担当で閉じる

後日 B に作り替えたくなった場合も、A が完成してからのほうが確実です。

## 9. 実装のヒント（ロジック担当）

素直に書くと上下左右で 4 通り必要になりますが、**「左に寄せる処理」1 つで済みます。**

```
左 : そのまま「左寄せ」
右 : 各行を反転 → 左寄せ → もう一度反転
上 : 盤面を転置 → 左寄せ → 転置で戻す
下 : 転置 → 反転 → 左寄せ → 反転 → 転置
```

「1 行を左に寄せる」も 3 手順です。

```
① 0（空き）を取り除く                    [0,2,0,2] → [2,2]
② 左から見て隣が同じなら合体し、次の 1 つを飛ばす  → [4]
③ 右側を 0 で埋めて長さ 4 に戻す           → [4,0,0,0]
```

②で「次の 1 つを飛ばす」のが、5 章 ① の罠への対策です。
